# ham-tcos-app

Just Another Ham Study: a free study guide for the US amateur radio exams, built from the
public-domain question pools published by the NCVEC. Live at
<https://ham.tcos.app>.

This is a child of [tcos-app](https://github.com/Twin-Cities-Open-Systems/tcos-app),
which hosts `tcos.app` and keeps the registry of apps on that domain.

The site has four pages: a landing page, the study page (guide, browse by
question, flashcards, practice exam, mastery and progress), a call-sign page,
and a Listen page that plays the spoken answer albums with the text read
along. Progress and preferences live in the browser's local storage; nothing
is sent anywhere.

## Layout

| Path | What it is |
| --- | --- |
| `index.html`, `study.html`, `callsign.html`, `listen.html` | the pages |
| `css/`, `js/` | styles and scripts, no third-party code, no external requests |
| `css/listen.css`, `js/listen.js` | the player: the Listen page, and the flashcards' Listen mode |
| `data/ham-study.json`, `data/ham-audio.json`, `data/ham-figures/` | generated by `build.py`; committed, and what ships |
| `audio/<pool>/` | 102 MB of committed MP3 and `.lrc`, plus each album's `cover.jpg`, built by `hee say` and staged with `build.py --stage-audio` |
| `build.py` | builds `data/` from `ham/`; `--check` fails if the committed data is stale |
| `ham/pools/` | the three NCVEC question pools and the 14 figures they reference |
| `ham/families.yaml` | groups the subelements into study families (colors) |
| `tests/` | the generator's tests |
| `robots.txt`, `sitemap.xml` | crawler policy and page list |
| `deploy.sh` | `lab` and `promote` steps, driven by `hee release` |
| `release.card.v1.yaml` | the release card `hee release` reads |
| `.github/workflows/ci.yml` | `hee-check`, data drift and tests, then publishes the lab payload from `main` |

## Question pools

`ham/pools/` is copied unchanged from the org's resume repo at commit `d8410a6`
(2026-09-12): Technician 2026-2030, General 2023-2027 and Extra 2024-2028,
1431 questions in all, as published by the NCVEC. Each pool card carries its
validity dates. When the NCVEC publishes a new pool, add it under `ham/pools/`,
add its subelements to `ham/families.yaml`, then rebuild.

## Listening

The three answers-only albums (Technician, General, Extra; ten tracks each,
one per subelement) are spoken by a local text-to-speech voice from the same
guide the study page shows. They are built outside this repo by `hee say`
from the album cards in the fleet's `ham/say/` directory, which also holds the
pronunciation lexicon and the cover art. The crib sheet album is not part of
the app.

Staging copies an album directory's numbered `.mp3` and `.lrc` pairs and its
`cover.jpg` into `audio/<pool>/`, then `build.py` reads every `.lrc` into
`data/ham-audio.json`: one line per timestamp, matched back to its question
id, split into the question and the answer so the page can colour them.

    python3 build.py --stage-audio /path/to/albums   # the three album dirs
    python3 build.py                                 # rewrites data/ham-audio.json

What the player does, on both pages:

- read-along from the `.lrc`: the line being spoken is highlighted and kept
  in view, questions in the text colour, answers in green;
- speed from 0.25x to 2x, remembered; the position in each track remembered;
- previous and next line, previous and next track, pause and play, as an
  overlay on the block being read;
- on the study page, **Listen** is a flashcard mode: the card body becomes
  the player, the card advances with the audio, and advancing the card plays
  its question.

The Listen page shows the albums with their covers and a tracklist; the
chosen album is remembered. Seeking needs a server that answers Range
requests, which `python3 -m http.server` does not; the lab and prod do.

## Rebuilding the data

    python3 build.py            # needs PyYAML; writes data/
    python3 build.py --check    # writes nothing; exit 2 if data/ is stale
    python3 -m unittest discover -s tests

Commit the regenerated `data/`: promote ships committed files with no rebuild.

## Releasing

Releases go through `hee release`, never by hand:

    hee release -lab              # confirm the lab serves main
    hee release -cut -yes         # release PR (the merge is the sign-off)
    hee release -promote -yes     # deploy to ham.tcos.app, signed prod tag
